# 复习站重构经验与维护规则

本文记录 CS603、CS605、CS608、CS616、CS618/636 复习站在 2026 年全面重构后得到的经验。它不是内容摘要，而是以后新增、校对和修复页面时必须执行的工作规则。

## 1. 资料的证据优先级

课程资料不能按“文件看起来正式”排序，必须按与当前考试的直接关联程度排序。

1. `2026` 开头的当年真题是题型、设问形式和考察范围的最强证据。
2. 当年课程讲义、教师资料和 sample 用来解释知识、补足定义，并确认题目所依赖的方法。
3. 历年真题可以提示可能覆盖的问题领域和常见变体，但不能覆盖当年真题给出的直接信号。
4. 个人复习材料可以作为讲解模式和详细程度的参考，尤其适合观察手写计算怎样逐行展开；其中的公式、数值和结论必须重新计算，不能因为写得详细就自动视为正确。
5. 网站自己生成的旧内容是待验证对象，不是证据来源。

若资料之间冲突，页面必须说明采用哪一份资料以及原因，不能静默拼接。

## 2. 两类页面承担不同任务

每门课继续保留两个页面，但二者不能只是同一内容换标题。

### 从零开始的预习/复习页

目标是让没有先修记忆的人从术语开始学完整个科目。

- 术语必须在首次使用前解释。
- 每个符号都要说明“它代表什么”和“本题在哪里得到它”。
- 每个方法先说明输入、输出和使用条件，再进入公式。
- 主例题负责完整示范，补充例题负责展示变体，不能用补充例题替代基础解释。
- 完整复习永久启用：主例题、补充例题和独立练习全部生成，但默认收起。完整复习表示内容不被删除或隐藏，不表示刷新后必须展开所有长答案。

### 从零开始攻克考试题页

目标是让学生能按题面完成作答并知道每一分从哪里来。

- 准确保留题目的输入、条件、分问和符号约定。
- 先把题面数据抄入工作区，再做第一步计算。
- 解答必须覆盖所有分问，不能把两个分问合并后遗漏其中的计算。
- 最后要有回代、边界、分支或安全性质检查。
- 概念题可以使用清楚的正文；数值题不能只给最终式或计算器结果。

## 3. 避免“知识的诅咒”

作者知道某个公式，不等于读者知道公式从哪里来。以下写法均视为不合格：

- “代入可得……”
- “逐行反向改写……”
- “同理……”
- “显然……”
- “用扩展欧几里得算法得到逆元……”
- “计算器得到余数……”
- 先使用 witness、commitment、invariant、certificate 等词，几段之后才解释。

合格解释需要回答四个问题：

1. 当前已有哪条等式、表格或状态？
2. 本步具体选择哪个量？
3. 对它做什么操作，为什么允许这样做？
4. 操作后哪个格、系数、集合、指针或状态发生了变化？

例如扩展欧几里得反代不能从一组除法等式跳到最终系数。必须逐行写出：

- 先从最后一条余数为 1 的等式单独留下 1；
- 本行准备消去哪个余数；
- 用前一条等式把该余数单独表示；
- 整块替换；
- 展开括号；
- 合并同类项；
- 最后从系数读出逆元并乘回检查。

## 4. 例题必须拥有完整输入

一个例题如果不给实际输入，就不能称为例题。

曾出现的错误包括：

- 3-SAT→CLIQUE 只说“公式有三个 clauses”，却没有给出公式；
- ECDSA 只列 `w、u1、u2、X、v` 的路线，没有一组可计算的点和签名；
- 零知识协议直接选择 response 并反算 commitment，却没有先解释验证等式和 challenge 的时序；
- Affine digraph 同时使用字母 `a` 和密钥参数 `a`，但没有区分二者。

完整例题至少要包含：

- 明确题目；
- 已知数据；
- 求解目标；
- 符号和编码约定；
- 每一步操作；
- 当前状态；
- 最终结果；
- 独立检查。

## 5. 表格展示“状态”，不是把说明文字装进格子

表格的用途是让学生看见算法对象怎样变化。表格不能只是三列“本步使用的等式／本步替换／当前等式”的文字复述。

决定是否使用表格前，先想象学生在考试答题纸上怎样写。若正常手写方式是一条接一条的等式，就应保留等式链，不能为了网页视觉统一而把它改造成表格。Affine 消元、模幂合并、ECC 坐标公式和零知识 transcript 通常属于这种情况。扩展 Euclid 系数递推、真值表、Decision Table、队列/visited 和矩阵状态才天然适合表格。

同一张计算表也不能在网页中机械重复十几次。只有当“前一行保留、下一行逐步填入”本身是算法要学习的内容时，才展示累计状态；否则显示一张考试时真正会写的完整表，并在正文中解释怎样填写。

当一个算法以表格计算时，必须遵守以下规则：

1. 第一步先展示完整表格，包括初始化行和尚未计算的行。
2. 每执行一个动作，重新展示当前完整表格。
3. 已完成的行继续保留。
4. 当前刚写入的行必须明确标记。
5. 未完成的行显示“待计算”，不能提前泄漏答案。
6. 表格旁的操作说明必须指出本步填写了哪一行、使用哪两行或移动了哪个指针。
7. 步骤编号与状态表的 `after` 索引必须对应，不能增补文字步骤后忘记移动后面的状态。
8. 同一个 `after` 不能出现两张互相竞争的状态表。
9. 每行列数必须与表头相同。

适合采用累计状态表的内容包括：

- Euclid、扩展 Euclid 和模逆；
- CRT 台账；
- 真值表和 decision table；
- BFS queue/visited；
- Hoare invariant 和数组指针；
- AES 4×4 state；
- RLWE 系数卷积与折回；
- ECC 点加法；
- backprop、pooling 和 attention；
- 测试条件、分支和规则覆盖。

纯概念比较和线性等式推导不应为了追求“每步一表”而制造无意义表格。表格必须对应真实变化的对象，也必须符合考试时合理的手写形式。

## 6. 每一个结果都要有来源和检查

“答案正确”不能替代过程。

- 模逆：展示除法/系数更新或逐行反代，并乘回得到余数 1。
- 模幂：展示指数拆分、逐次平方、选择哪些幂以及最终取模。
- CRT：展示部分模数、逆元、加权项、求和、最终取模和逐模回代。
- 平方根：每个候选根都实际平方并显示商和余数。
- ECC：分别展示分子、分母、分母逆元、斜率、`x₃`、`y₃` 和曲线回代。
- Rabin：展示 `R²=qN+C`，验证 oracle 返回值满足同一余数，再计算两个 gcd 并把因子乘回。
- 测试题：每个 test case 都要对应具体 branch、partition 或 rule，不能只写“增加测试”。
- 证明题：正向、反向、终止性或复杂度不能只出现结论。

大整数也不能用“太大，交给计算器”跳过。可以允许工具执行乘法，但页面仍要写出被除数、商、模数和余数，使结果可以独立复核。

## 7. 语言要直接，不要用学习气氛代替教学

以下表达没有提供学科信息，应删除：

- “沿着小台阶走，每步停一下。”
- “上一站负责准备地基。”
- “这一关新增计算地基。”
- “看不懂新词时不需要假装已经会。”

它们可以被更有用的句子替代：

- “本节先定义模同余，再用它解释模逆。”
- “使用 189 前，先验证 `93×189≡1 (mod 676)`。”
- “本步只把余数 33 替换为 `109−76`，其他项不动。”

STE 风格在本站中的含义是：

- 主语和动作明确；
- 一个句子尽量只承担一个推理动作；
- 先写事实，再写因果；
- 不用隐喻掩盖术语；
- 中英文术语第一次出现时并列，之后保持同一写法；
- 不把鼓励语当成解释。

## 8. 事实校验必须与教学质量分开检查

一份答案可能数值正确但无法学习，也可能解释顺畅但事实错误。两项必须分别审核。

事实审核至少包括：

- 对照当年真题确认问题文字、分问、符号和给定值；
- 对照课程资料确认公式适用条件；
- 用独立计算复核关键数值；
- 检查所有回代；
- 检查图、表和正文是否使用同一变量；
- 检查旧题或个人材料没有被误标为当年真题；
- 检查推断性内容明确标为补充，而非真题直接要求。

教学审核至少包括：

- 术语是否先解释后使用；
- 是否存在结果跳步；
- 是否能从上一状态推出下一状态；
- 学生是否知道为什么选择这个方法；
- 例题是否给齐全部输入；
- 最终检查是否能发现常见抄写或符号错误。

## 9. 数据修复脚本的工程经验

当前网站使用基础数据加课程修复脚本：

- `revision-data.js`：课程入口、资料优先级和摘要；
- `revision-depth.js`：基础教学与考题数据；
- `repair-cs603-605.js`、`repair-cs608.js`、`repair-cs616.js`、`repair-cs618.js`：经过事实校验和教学重写后的覆盖层；
- `revision.js`：统一渲染；
- `revision.css`：统一状态表和完整复习显示。

维护时应注意：

1. 修复脚本必须在 `revision-depth.js` 之后、`revision.js` 之前载入。
2. 改 `steps` 数组长度时，必须同步检查所有状态表的 `after`。
3. 覆盖旧状态时先按 `after` 删除，再插入并排序。
4. 学习例题和考试题若共享过程，应该复制已经验证的数据，避免手工维护两套不同答案。
5. 不要依赖浏览器人工点击才发现结构错误；先用脚本检查重复索引、越界索引、列宽和缺失行。
6. 完整复习的显示规则由统一渲染器控制，不能只在某一门课里强制重开 `<details>`。

## 10. 长页面的展开与定位规则

完整内容和默认展开是两件不同的事。复习站必须包含全部主例题、补充例题和独立练习，但不应在页面载入时同时展开它们。

- 学习页的主例题、补充例题和独立练习使用 `<details>`，默认不写 `open`。
- 考试页的小问答案同样默认收起；“展开所有小问”只由用户主动触发。
- 不得用课程专属脚本在 `toggle` 后强制重新打开内容。
- 页面文案应写“列出全部内容，默认收起”，不能把“完整复习”描述成“自动展开全部”。
- 修改展开规则后，要刷新每门课的长页面，确认用户不需要跨过大量答案才能回到原章节。
- 默认收起不能变成内容隐藏：所有例题标题必须仍在 DOM 和页面阅读顺序中，用户无需切换模式才能找到补充例题。
- 打印样式可以展开 `<details>` 的内部内容，因为打印目标是得到完整材料；屏幕浏览与打印的默认行为可以不同。

这条规则的判断标准是：刷新页面后，章节位置应该容易重新找到；需要阅读哪道题，由用户点击决定。

页面还应只保留直接帮助学习或答题的内容。统一渲染器不得在每门课末尾自动添加“错误定位、复习方法、训练方法、完成清单、资料库”等通用管理区块。资料仍作为内容校对来源保存在项目中，但不需要在每个学生页面重复列出。若某项提示对一道题确实必要，应写进该题的解释或检查步骤，而不是另建泛泛的页面尾部板块。

复习站必须是一站式学习材料。`2pass` 中的 PDF、sample、讲义和历年真题是编辑与事实校对的依据，不是用来弥补网页解释缺失的学生跳转入口。学生页面不得提供“打开 PDF 后继续学习”之类的链接；如果离开网站才能理解某个单元或完成某道题，就说明该网页内容尚未完成。

侧栏目录必须反映当前科目的真实内容结构：

- 学习页逐项列出该科目的每个学习单元，并链接到对应的 `stage-N`。
- 考题页逐项列出该科目的每道考题，并链接到对应的 `qN`。
- 不得只写“课程内容”或“真题答案”这种不能帮助定位的总标题。
- 目录标题必须直接来自课程数据，目录中的每个锚点都必须在当前页面存在。

模运算的模数属于表达式本身，不能依赖读者从上一行猜测。尤其在求逆、消元、两边乘逆元、回代和最终检查时，每条同余式都应写成 `x≡y (mod n)`；不得把 `x≡y` 与 `mod n` 拆进互不相邻的表格单元，也不得只写 `a=19` 来代替 `a≡19 (mod 676)`。若需要选取标准代表元，应先写完整同余式，再明确说明“取标准代表元 a=19”。

扩展 Euclid 的“完整过程”不能是一条塞满连续等号的反代链。至少应分开写：每一次带余除法、最后非零余数与 gcd、从余数 1 的等式开始、改写下一条待代入等式、一次只替换一个余数、展开括号、合并系数、写成 Bézout 形式、取模读出逆元、乘回验证。随后若用逆元解同余式，还要另外展示两边同乘、逆元化为 1、结果取标准余数。任何一句“反代可得”都不能代替这些操作。

相邻计算步骤必须用完整的数学式交接。若本步算出一个余数、坐标、表格状态或逻辑结论，而下一步要把它代入另一条公式，本步末尾必须写出下一步实际接收的完整式子。例如，由 `2⁴≡5 (mod 11)` 和 `2⁴≡3t (mod 11)` 必须在本步明确写成 `5≡3t (mod 11)`；不能只说“两边余数相同”，然后让下一步突然出现 `3t≡5 (mod 11)`。如果交换等式或同余式的左右两边，也要明确说明这只是同一关系的改写。

“两边同乘逆元”不能直接跳到未知量的答案。必须依次写出：回到待解的完整同余式、左右两边实际乘上哪个逆元、用交换律和结合律把“系数×逆元”放在一起、引用乘回检查把该乘积化为 1、只留下未知量、计算另一边乘积并取模、最后写标准代表元。求出了逆元，只代表得到了下一步要用的工具，不代表已经完成消元。

术语不能充当解释。安全题写 `oracle` 时，必须先交代攻击者提交什么、服务器返回或泄漏什么、攻击者如何反复试探、这些观察怎样一步步变成秘密线索，然后再给这种问答接口命名。测试题首次出现 TCI、test oracle、proof obligation 或 frame 时，必须先用当前题的具体输入、输出或状态说明它指什么。机器学习题出现 Jacobian、softmax saturation、identity mapping 或 activation 时，至少给一个低维数字例子或可观察过程；不能用一串英文术语互相定义。

公式中的减法顺序、正负号和逆元方向必须从当前采用的参数式推导，不能只给“套公式”的结果。例如 CRT/Garner 若先设 `x=a_p+pu`，就要逐行推出 `pu≡a_q−a_p (mod q)`，再得到 `u≡(a_q−a_p)p⁻¹ (mod q)`。若读者可能自然地问“为什么不是反过来减”，应代入反向写法展示它在其余公式不变时无法通过哪一条回代检查，并说明只有同时改变参数式，反向差值才可能成立。

不要把计算器能够直接完成的普通 `A mod n` 强行拆成“先求整数商 q，再算 A−qn”。在 CRT、模幂、平方根回代等题中，若商不参与后续公式，直接写完整输入 `A mod n` 和余数即可；额外的商是无用步骤。只有扩展 Euclid 等算法本身需要商来生成下一行余数或系数时，才保留 q 列和带余除法过程。

有限域中的“除法”必须显式改写成“乘分母的逆元”。求出逆元后不能突然出现两个没有来源的数字相乘。斜率计算至少要连续写出：原斜率公式、代入点坐标后得到的分子和分母、`λ≡分子×分母⁻¹ (mod p)`、求得的完整逆元同余式、把逆元代回、直接取模得到 λ。后续坐标公式再明确代入这个 λ。

“不漏过程”不等于把两套算法串在同一道题里重复计算同一结果。选用 PDF 式扩展 Euclid 系数表时，逐行更新 `r` 与 `d` 已经是一条完整求逆路线；不能在表格算出逆元后再追加一整套传统反向代入，除非题目明确要求比较两种方法。表格只在格子发生变化时展示新状态；读取结果、化标准余数和乘回验证使用普通算式说明，不重复展示一张完全没变的表。

## 11. 发布前检查清单

每次更新后至少执行：

- [ ] `node --check` 检查所有数据与修复脚本。
- [ ] 在 VM 中按页面实际顺序载入基础数据和全部修复脚本。
- [ ] 检查每个 state 的 `after` 在步骤范围内。
- [ ] 检查同一题没有重复 `after`。
- [ ] 检查数组行或 `cells` 的宽度与表头一致。
- [ ] 检查所有数值步骤是否有计算过程或真实状态表。
- [ ] 重新计算密码学、算法和统计例题的关键结果。
- [ ] 检查当年真题、sample、历年真题和个人材料的标签没有混淆。
- [ ] 检查所有补充例题仍在完整复习中显示。
- [ ] 检查所有例题和独立练习默认收起，标题仍全部可见。
- [ ] 刷新长页面，确认展开规则不会制造过长的初始页面。
- [ ] 检查学生页面没有指向 PDF 或资料库的学习跳转链接。
- [ ] 检查学习页的全部单元目录和考题页的全部题目目录均能定位到真实内容。
- [ ] 执行 `git diff --check`。
- [ ] 提交前查看 `git status`，确认没有遗漏资料或误收无关文件。

## 12. 本轮最重要的结论

复习站的目标不是“页面里有答案”，而是学生能在不知道中间结论的情况下，从题面走到答案。判断一段内容是否完成时，应问：

> 如果把最终答案遮住，一个第一次学习的人能否只依靠当前页面，解释每个新符号、完成每一步操作，并独立检查结果？

只要答案是否定的，这一节就仍然没有完成。
